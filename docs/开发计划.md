# NyaSmsForward Client-Node（Android）开发计划

> 状态：**M0 脚手架已完成**，下一步 M1（配对页 + 接收 + 上报）。
> 本仓库独立于 `nyasmsforward-server` 和 `nyasmsforward-client`，只通过服务端仓库的 `docs/协议.md` 对接（配对 `pair/claim`、上报 `device/messages`、WebSocket `device/ws`）。交互原型见服务端仓库 `docs/prototype.html` 的 Android 页。

## 1. 选型：原生 Kotlin + Jetpack Compose

核心能力（短信广播接收、前台服务、SmsManager、多 SIM、WorkManager、Room）全部是 Android 原生 API。Flutter / React Native 也要为这些写平台通道，反而更重。UI 只有状态页 + 设置页 + 配对页，Compose 足够。

包名 `app.nya.smsforward.node`（对应 NyaAccounting 的 `app.nya.accounting`；同一台手机上如果也装了 client，则 client 是 `app.nya.smsforward.client`，两者互不冲突）；`minSdk 26`，`targetSdk` 取当前稳定版。

> 这个 App 装在**放 SIM 卡收短信的那台手机**上，是“接收端”。你平时用来看短信的主力手机装的是 `nyasmsforward-client`。

## 2.1 连接平台：配对与长期登录

**只需要连接一次。** 接收端通常放在角落里长期运行，不应该被要求重新登录，所以设计目标是：配对之后，重启手机、服务器重启、断网几天、换域名都不需要人再碰它。

**首次配对（配对页）**

1. 填**服务器地址** + **配对码**（Web「设备与客户端」里生成，10 分钟有效，一次性），或点「扫码」（`mobile_scanner` 同类方案 / CameraX + ML Kit）填入。可改设备名称。**配对码输入框要容忍空格**：Web 上展示为 `483 920`，输入时先滤掉非数字再限长为 6，粘贴带空格的码也要能用（client 的 M0 已在这上面踩过坑：直接 `maxLength=6` 会把 `483 920` 截成 5 位数字）。
2. 地址校验：必须 `https://`；只有 `localhost` / 局域网地址（10.x / 172.16–31.x / 192.168.x）允许 `http://`，并提示风险。
3. `POST /pair/claim`（`kind=phone`，带 `sims`、`appVersion`）→ 拿到 `deviceId` + 长期令牌。
4. 令牌存 **Android Keystore 加密**的存储（`EncryptedSharedPreferences` / DataStore + Keystore 密钥），不写明文文件。
5. **接收端只能用配对码，没有“账号登录”**——放在角落里收短信的手机不应该持有管理员密码。

**日常运行**

- 所有请求带 `Authorization: Bearer <token>`；不放 URL。
- **判定“需要重新配对”必须严格**（协议 §2.2）：只有 `401` + JSON `token_revoked / token_invalid / token_expired`（或 WebSocket 关闭码 `4401`）才进入“未配对”。网络错误、超时、`429`、`5xx`、裸 401（反代拦截）、`403` / `404` 一律**保留令牌**，指数退避重试（1s 起，上限 5 分钟，带抖动），无限重试。
- 进入“未配对”后：
  - 停止上传和 WebSocket，前台服务保留一条“需要重新配对”的通知（点开进配对页）；
  - **短信继续接收，本地 outbox 完整保留**，不丢；
  - 重新配对成功后自动补传，靠 `dedupeKey` 去重。
- **重新配对**：Web 对该设备点“重新配对”得到新配对码，在配对页输入即可——`deviceId` 不变，历史会话和策略沿用。如果只是清空 App 数据重装，也用同样的方式。
- 开机后（`RECEIVE_BOOT_COMPLETED`）自动读取令牌、恢复连接和前台服务，不需要打开 App。

**连接设置页**

- 服务器地址（可改；**改地址不需要重新配对**，保存后用 `GET /me` 验证并自动重连）。
- 设备名称、登录令牌状态（“长期有效 · 不会自动过期”）、当前连接状态和最近一次成功上报时间。
- 「测试连接」（调 `/me`，显示服务器版本、令牌是否有效）、「立即同步」。
- 可选：**证书指纹固定**（使用自签名证书时，默认关）。
- 「断开并清除令牌」（二次确认；**本地未上报队列保留**，并提示这一点）。

## 3. 接收与上报

1. `SmsReceiver`（Manifest 静态注册 `android.provider.Telephony.SMS_RECEIVED`）→ `Telephony.Sms.Intents.getMessagesFromIntent` → **按发件人拼接多段短信**（长短信会拆成多个 PDU）→ 由 `subscriptionId` 换算 SIM 槽位。
2. `goAsync()` 内写入 Room outbox，并计算 `dedupeKey = sha256(deviceId|simSlot|peer|deviceTime|body)`；同时更新 `recent_peers(peer_key, last_seen_at)` 表（记录“最近给本机发过短信的号码”，供“仅回复”模式校验，与服务端无关）。
3. 入队 `UploadWorker`（WorkManager，联网约束，指数退避），批量 `POST /device/messages`；按返回的逐条 `status` 标记已上报或保留重试（`duplicate` 视为成功，`rejected` 不重试）。
4. 应用启动、网络恢复、点“立即同步”时也会 flush。
5. 可选：同步发出的短信、回补历史（见 §3.1，需要 `READ_SMS`，**默认关**）。

## 3.1 同步手机上发出的短信 / 回补历史（可选，默认关闭）

默认只“收”。为了让会话完整（Web / 客户端里能看到你在手机自带短信 App 里手动回的那条），提供两个**互相独立、由用户选择**的开关，都在“同步范围”设置里：

| 开关 | 做什么 | 默认 |
|---|---|---|
| 同步在手机自带短信 App 里发出的短信 | 读取系统发件箱，新增的以 `direction=out` 上报（服务端记为 `origin=device`） | 关 |
| 回补历史短信（关 / 7 天 / 30 天） | 首次开启时把收件箱 + 发件箱最近 N 天上报，带 `backfill=true` | 关 |

**权限**：两项都需要 `READ_SMS`。这是比 `RECEIVE_SMS` 敏感得多的权限（能读全部历史短信），所以**只在用户打开开关的那一刻才申请**；两个开关都关闭时，App 不持有也不申请它。用户关掉开关后手机立即停止读取（服务端已有数据保留）。

**实现**

- `ContentObserver` 监听 `Telephony.Sms.CONTENT_URI`，变化时按 `_id` 游标（本地保存 `last_sent_id`）查询 `type = MESSAGE_TYPE_SENT` 的新行，取 `address`、`body`、`date`、`sub_id`（换算成 SIM 槽位）。只处理 SMS，不处理 MMS。
- 首次开启时游标初始化为当前最大 `_id`，**只同步开启之后发出的**；历史靠“回补”开关单独控制，避免开开关就把整个发件箱倒出去。
- **去重（避免经平台发出的短信重复出现）**：手机记录每个平台下发任务的 `platform_sent(peer_key, body_hash, sent_at)`，读取发件箱时若匹配（同号码 + 同正文 + 5 分钟内）就跳过；服务端还有一层兜底（协议 §5.1）。第三方（非默认短信）App 通过 `SmsManager` 发送的短信，系统通常不会写入发件箱，所以这一层主要防个别 ROM 会写入的情况。
- 回补：分页读取，每批 ≤ 100 条走同一个上报队列，带 `backfill=true`；进度显示在设置页。
- **不触发通知、自动标为已读**：`origin=device` 的发出短信和回补短信，服务端入库即置已读，SSE 带 `notify=false`，各客户端不弹通知。

**限制**：只能读到默认短信 App 写入系统数据库的内容；部分 ROM 的“加密短信 / 私密短信 / 短信保险箱”不在系统数据库里，读不到。侧载安装可能需要先在“应用信息 → 允许受限制的设置”里放开短信权限（见 §6）。

## 4. 下发：回复与新发（可选）

### 4.1 本地策略（默认“关闭”，只能在手机上改）

| 策略 | 行为 |
|---|---|
| 关闭 | 不启动前台服务，不连 WebSocket；只收不发 |
| 仅回复 | 启动前台服务；只接受 `mode=reply`，且收件人必须在 `recent_peers` 里（最近 7 天来信，可调）|
| 允许新发 | 允许回复，也允许 `mode=new` 向任意号码发送 |

另有：每小时上限（默认 10）、任务过期（默认 10 分钟）丢弃、可选收件人白名单。当前策略通过 WebSocket `hello` 上报给服务端（用于 Web 展示“实际生效”）。

**校验以手机本地数据为准**：`mode` 字段由服务端给出，但手机不信任它——无论服务端声称是什么模式，只要收件人不在 `recent_peers` 里，就必须策略为“允许新发”才会发送。这样服务端被攻破也无法把“仅回复”的手机当群发工具。

### 4.2 收到 `send_sms` 后

1. 校验：策略 → 收件人（`recent_peers` / 白名单）→ 频率 → 过期 → `SEND_SMS` 权限。任一不满足直接回 `send_result{status:"failed", error:…}`（错误码见协议 §6.2）。
2. **选卡**：按 `simSlot` 找到当前对应的 `subscriptionId`，用 `SmsManager.getSmsManagerForSubscriptionId(subId)` 发送——回复必须用**原来收信的那张卡**发出，对方才认得这个号码。槽位当前无卡则回 `sim_unavailable`，**不自动改用另一张卡**。
3. `divideMessage` + `sendMultipartTextMessage`，`sentIntent` / `deliveryIntent` 回报 `sent` / `delivered` / `failed`。
4. 经平台发出的短信手机**不**再上报：服务端在收到 `sent` 后自行生成 `direction=out`（`origin=platform`）的记录并关联原短信。（在手机自带短信 App 里手动发出的短信，仅在开启“同步发出的短信”后才上报，见 §3.1。）

### 4.3 无法回复的情况

- 发件人是字母 / 名称 ID（如“示例银行”）：运营商不支持向它发短信，服务端在创建任务时就会拒绝（`reply_not_supported`）。
- 106 等服务号：可以发，但通常只识别 TD / Y / 1 之类的指令，是否有效取决于对方，`delivered` 只代表运营商已投递。

只收不发时不启动前台服务。

## 5. 权限

`RECEIVE_SMS`（必需）· `SEND_SMS`（下发才需要）· `READ_SMS`（仅在用户开启“同步发出的短信 / 回补历史”时才申请）· `READ_PHONE_STATE`（多 SIM 信息）· `POST_NOTIFICATIONS` · `FOREGROUND_SERVICE` + 对应类型 · `RECEIVE_BOOT_COMPLETED` · `INTERNET`。

## 6. 现实约束（首次使用引导里要说明）

- **不上 Google Play**：Play 对 SMS 权限限制很严，只允许默认短信应用。发布方式为 GitHub Release 签名 APK。
- **侧载后权限可能被限制**：Android 13+ 侧载应用的短信权限可能需要在“应用信息 → ⋮ → 允许受限制的设置”里放开。
- **国产 ROM 保活**：引导开启自启动、关闭电池优化（`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`）；部分 ROM（如小米）对“通知类短信”有单独开关。
- 双卡：上报带槽位，发送可选 SIM；运营商号码通常读不到，只显示运营商名 + 槽位。
- 只支持普通 SMS（不含 MMS / RCS）。

## 7. CI 与发布

- **CI**（push / PR）：`./gradlew lint testDebugUnitTest assembleDebug`。Actions 固定 commit SHA。
- **Release**（推送 `v*` 标签）：校验 tag 与 `VERSION` 一致；用 secrets（`ANDROID_KEYSTORE_BASE64`、`ANDROID_KEYSTORE_PASSWORD`、`ANDROID_KEY_ALIAS`、`ANDROID_KEY_PASSWORD`）还原 keystore，`assembleRelease` 签名，APK 上传 GitHub Release（沿用 NyaAccounting 的流程）。

## 8. 里程碑

- **M0（已完成）**：Gradle 工程骨架（Kotlin 2.4 + Compose，minSdk 26 / targetSdk 36）、CI 与签名发布工作流；`SendPolicy`、`PeerKey`、`DedupeKey`、`ServerUrl`、`Connection` / `Backoff` 已实现并有单元测试（向量与协议 §5.2 一致）。
- **M1**：配对页 + 连接设置 + 接收 + 本地队列 + 上报 + 状态页。验收：真机收短信 10 秒内出现在 Web；断网重连不丢不重；重启手机 / 服务器后无需重新配对；Web 吊销令牌后短信在本地继续攒着，重新配对后自动补传。
- **M3**：前台服务 + WebSocket + SmsManager + 三档本地策略 + `recent_peers` 校验 + 按槽位选卡 + 回执。验收：回复用原来收信的那张卡发出；“仅回复”的手机拒绝发给非最近来信号码的任务。
- **M4**：同步发件箱（ContentObserver + 游标）、历史回补、`platform_sent` 去重、按需申请 `READ_SMS`、“同步范围”设置页。验收：开启同步后在手机短信 App 里手动发一条，几秒内出现在 Web / 客户端会话里，标注“手机上发出”，不弹通知；经平台发出的短信不重复；关闭开关后不再读取。
- **M6**：签名 APK + 首次使用引导（权限、受限设置、保活）。
